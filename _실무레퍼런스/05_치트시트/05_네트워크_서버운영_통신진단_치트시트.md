## 1. 포트(Port) 충돌 해결 및 유령 프로세스 강제 종료

서버 구동 시 `Address already in use (WinError 10048)` 에러가 발생하면 아래 명령어로 해당 포트를 점유 중인 프로세스(PID)를 찾아 종료합니다.

### 1.1. Windows (PowerShell / CMD)
```powershell
# [사전 설정] PowerShell 한글 출력 깨짐 방지
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8

# 1. 특정 포트(예: 8000번)를 점유 중인 프로세스(PID) 찾기 (가장 마지막 숫자가 PID)
netstat -ano | findstr :8000

# 2. 해당 PID(예: 12345)가 어떤 프로그램인지 이름 확인
tasklist | findstr 12345
# 또는 PowerShell 전용 명령어로 프로세스 이름과 경로 확인
Get-Process -Id (Get-NetTCPConnection -LocalPort 8000).OwningProcess

# 3. 해당 PID(예: 12345) 강제 종료 (/F: 강제, /T: 하위 자식 프로세스 트리까지 함께 종료)
taskkill /PID 12345 /F /T

# 4. [한 줄 즉시 종료] 8000번 포트를 점유 중인 프로세스를 찾아 즉시 강제 종료 (PowerShell)
Get-NetTCPConnection -LocalPort 8000 -ErrorAction SilentlyContinue | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }

# 5. 응답 없는 파이썬(python.exe) 또는 노드(node.exe) 전체 일괄 종료
taskkill /IM python.exe /F
taskkill /IM node.exe /F
```

### 1.2. Linux (Ubuntu / Debian / Rocky)
```bash
# 1. 특정 포트(예: 8000번) 점유 프로세스 확인
sudo lsof -i :8000
sudo ss -tulpn | grep :8000

# 2. PID(예: 12345) 즉시 강제 종료 (-9: SIGKILL)
sudo kill -9 12345

# 3. [한 줄 즉시 종료] 8000번 TCP 포트 점유 프로세스 강제 종료
sudo fuser -k 8000/tcp
```

## 2. 장비 통신 및 원격 포트 개방(방화벽/라우팅) 정밀 진단

일반 `ping`은 ICMP 프로토콜만 확인하므로, `ping` 성공 여부와 무관하게 실제 장비 TCP 포트가 열려 있는지 확인하려면 반드시 TCP 연결 테스트를 수행해야 합니다.

### 2.1. Windows PowerShell에서 TCP 포트 개방 확인 (`telnet` 설치 불필요)
```powershell
# 1. 기본 핑 테스트 및 연속 핑 테스트 (종료는 Ctrl+C)
ping 50.0.31.100
ping -t 50.0.31.100

# 2. [핵심] 특정 IP의 특정 TCP 포트(예: 8701) 개방 여부 테스트 (TcpTestSucceeded : True 확인)
Test-NetConnection -ComputerName 50.0.31.100 -Port 8701
tnc 50.0.31.100 -Port 8701

# 3. 복수 포트(8701~8705)가 열려 있는지 1초 타임아웃으로 빠르게 연속 점검하는 스크립트
8701..8705 | ForEach-Object {
    $port = $_
    $tcp = New-Object System.Net.Sockets.TcpClient
    $connect = $tcp.BeginConnect("50.0.31.100", $port, $null, $null)
    $wait = $connect.AsyncWaitHandle.WaitOne(1000, $false)
    if ($wait -and $tcp.Connected) {
        Write-Host "[성공] 50.0.31.100:$port 열림" -ForegroundColor Green
    } else {
        Write-Host "[실패] 50.0.31.100:$port 닫힘/응답없음" -ForegroundColor Red
    }
    $tcp.Close()
}

# 4. 목적지 장비까지 어느 라우터(게이트웨이) 구간에서 단절되는지 경로 추적 (-d: DNS 역조회 생략)
tracert -d 50.0.31.100
```

### 2.2. Linux에서 TCP/UDP 포트 및 HTTP API 테스트
```bash
# 1. netcat(nc)으로 원격 IP의 특정 TCP 포트(8701) 개방 여부 확인 (-w 2: 타임아웃 2초)
nc -zv -w 2 50.0.31.100 8701

# 2. 포트 범위(8701~8708) 일괄 개방 확인
nc -zv -w 1 50.0.31.100 8701-8708

# 3. 간이 TCP 수신 리스너 띄우기 (방화벽 개방 여부 양방향 테스트용)
nc -l -p 8701 -v

# 4. curl로 웹/API 서버 응답 헤더 및 상태코드 확인
curl -I http://localhost:8000/health

# 5. curl로 JSON POST 요청 전송 테스트
curl -X POST http://localhost:8000/api/nodes \
  -H "Content-Type: application/json" \
  -d '{"node_id": "SRV01", "status": 0}'
```

## 3. 윈도우 방화벽(Windows Firewall) 명령어 한 줄 제어

관리자 권한 PowerShell 또는 CMD에서 인바운드 규칙을 즉시 추가/조회/삭제하는 명령어입니다.

```powershell
# 1. 단일 TCP 포트(8000번) 인바운드 허용 규칙 추가
netsh advfirewall firewall add rule name="App_Web_8000" dir=in action=allow protocol=TCP localport=8000

# 2. 연속된 TCP 포트 범위(9001~9005번) 일괄 인바운드 허용 규칙 추가
netsh advfirewall firewall add rule name="App_TCP_9001_9005" dir=in action=allow protocol=TCP localport=9001-9005

# 3. 특정 IP 대역(예: 10.0.0.0/8 사내망)에서 들어오는 접속만 허용
netsh advfirewall firewall add rule name="App_Internal_Net" dir=in action=allow protocol=TCP localport=9001-9005 remoteip=10.0.0.0/8

# 4. 등록한 방화벽 규칙 조회 및 삭제
netsh advfirewall firewall show rule name="App_TCP_9001_9005"
netsh advfirewall firewall delete rule name="App_TCP_9001_9005"
```

## 4. 실시간 네트워크 연결 상태 및 장비 접속 대수 모니터링

```powershell
# [Windows] 1. 특정 포트(8701)에 현재 연결된(ESTABLISHED) 장비 IP 목록 확인
netstat -an | findstr :8701 | findstr ESTABLISHED

# [Windows] 2. 8701 포트에 현재 접속 중인 장비 대수(Count) 숫자만 출력
(Get-NetTCPConnection -LocalPort 8701 -State Established -ErrorAction SilentlyContinue).Count

# [Windows] 3. 전체 TCP 연결 상태별(Established, TimeWait, CloseWait 등) 개수 요약
Get-NetTCPConnection | Group-Object State | Select-Object Name, Count
```

```bash
# [Linux] 1. 상태별 전체 TCP 소켓 요약 통계
ss -s

# [Linux] 2. 8701 포트에 연결된 클라이언트 IP별 접속 개수 상위 정렬
ss -tn state established '( sport = :8701 )' | awk 'NR>1 {print $4}' | cut -d: -f1 | sort | uniq -c | sort -nr | head -n 20
```

## 5. 파이썬/실행파일을 무인 백그라운드 서비스로 등록하기

### 5.1. Windows: `WinSW` (Windows Service Wrapper) 표준 설정
1. `WinSW-x64.exe`를 프로젝트 폴더(예: `C:\AppServer\`)에 복사하고 이름을 `app-service.exe`로 변경합니다.
2. 동일 폴더에 `app-service.xml` 파일을 아래와 같이 작성합니다:
```xml
<service>
  <id>app-server</id>
  <name>App Backend Service</name>
  <description>통합 API 및 백그라운드 워커 서버</description>
  <workingdirectory>C:\AppServer</workingdirectory>
  <executable>uv</executable>
  <arguments>run python main.py</arguments>
  <onfailure action="restart" delay="5 sec"/>
  <log mode="roll-by-size-time">
    <sizeThreshold>10240</sizeThreshold>
    <pattern>yyyyMMdd</pattern>
    <autoRollAtTime>00:00:00</autoRollAtTime>
  </log>
</service>
```
3. 관리자 권한 PowerShell에서 서비스를 등록 및 시작합니다:
```powershell
.\app-service.exe install
.\app-service.exe start
.\app-service.exe status
.\app-service.exe restart
.\app-service.exe stop
.\app-service.exe uninstall
```

### 5.2. Linux: `systemd` 서비스 등록 (`/etc/systemd/system/app-server.service`)
```ini
[Unit]
Description=FastAPI & Background Worker Server
After=network.target postgresql.service

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/home/ubuntu/app-server
ExecStart=/home/ubuntu/.local/bin/uv run uvicorn app.main:app --host 0.0.0.0 --port 8000
Restart=always
RestartSec=3
Environment="TZ=Asia/Seoul"

[Install]
WantedBy=multi-user.target
```
```bash
sudo systemctl daemon-reload
sudo systemctl enable --now app-server
sudo systemctl status app-server
sudo journalctl -u app-server -f -n 100
```

## 6. SSH 원격 접속 및 SSH 로컬 포트포워딩(`-L`)

### 6.1. 비밀번호 입력 없는 SSH 키 등록 및 `~/.ssh/config` 설정
```bash
# 1. 내 PC에서 Ed25519 SSH 키 생성
ssh-keygen -t ed25519

# 2. 공개키를 원격 서버에 등록 (Windows PowerShell)
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh ubuntu@192.168.0.100 "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
```
`%USERPROFILE%\.ssh\config` 설정 예시:
```sshconfig
Host app-prod
    HostName 192.168.0.100
    User ubuntu
    Port 22
    IdentityFile ~/.ssh/id_ed25519
    ServerAliveInterval 60
```

### 6.2. SSH 로컬 포트포워딩 (`-L`: 원격지 내부 포트를 내 PC 로컬 포트로 연결)
```bash
# 사례 1: 원격 서버(app-prod) 내부의 PostgreSQL(127.0.0.1:5432)을 내 PC의 localhost:15432로 연결
ssh -N -L 15432:127.0.0.1:5432 app-prod

# 사례 2: 원격 서버에서만 접근 가능한 내부 관리 콘솔(10.0.1.100:8080) 화면을 내 PC의 http://localhost:9080 으로 연결
ssh -N -L 9080:10.0.1.100:8080 app-prod
```

## 7. 패킷 캡처 및 바이너리 통신 분석 (`tcpdump`, `tshark`, `Wireshark`)

### 7.1. Linux `tcpdump` 및 Windows/Linux `tshark` 명령어
```bash
# 1. [Linux] 특정 포트(9001) 패킷을 Hex 및 ASCII 형태로 실시간 출력 (-X)
sudo tcpdump -i any tcp port 9001 -nn -X

# 2. [Linux] 특정 호스트 IP(10.0.1.100)와 주고받는 패킷을 capture.pcap 파일로 저장
sudo tcpdump -i any host 10.0.1.100 and tcp port 9001 -w capture.pcap

# 3. [Windows/Linux] 캡처된 .pcap 파일에서 실제 페이로드(Hex 데이터)만 추출하여 AI 분석에 전달 (tshark)
tshark -r capture.pcap -Y "tcp.port == 9001 && tcp.len > 0" -T fields -e frame.time -e ip.src -e tcp.payload
```

### 7.2. `Wireshark` 상단 Display Filter 필수 표현식 6선
```text
# 1. 특정 호스트 IP와 오가는 패킷만 표시
ip.addr == 10.0.1.100

# 2. 특정 TCP 포트(9001) 통신만 표시
tcp.port == 9001

# 3. 특정 호스트 IP이면서 특정 포트인 패킷만 표시
ip.addr == 10.0.1.100 && tcp.port == 9001

# 4. 빈 ACK 패킷을 제외하고 실제 데이터 페이로드가 존재하는 패킷만 표시
ip.addr == 10.0.1.100 && tcp.port == 9001 && tcp.len > 0

# 5. 통신 재전송(Retransmission) 또는 강제 연결 종료(RST) 장애 패킷만 필터링
tcp.analysis.retransmission || tcp.flags.reset == 1

# 6. 패킷 본문 내 특정 문자열(예: 노드 식별자 "SRV01") 포함 패킷 검색
tcp contains "SRV01"
```
