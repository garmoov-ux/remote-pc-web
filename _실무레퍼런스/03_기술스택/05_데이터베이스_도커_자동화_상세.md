## 2. 5대 데이터베이스 선택 기준 (실사용 빈도순 배치)

현재 가장 많이 사용하는 주력 데이터베이스부터 레거시 호환용 순서로 정리했습니다.

### 2.1. 데이터베이스별 특성 및 추천 프로젝트 (1순위 -> 5순위)

#### 1순위. PostgreSQL 16+ (서버 RDBMS 표준)
- **동작 방식 및 드라이버**: 클라이언트-서버 RDBMS이며, 비동기 `asyncpg` / `psycopg 3` + `SQLAlchemy 2.0`을 사용합니다.
- **장점 및 추천 대상**: 현존 최고의 오픈소스 RDBMS입니다. 동시 접속 처리, 대용량 테이블 월별 파티셔닝, `JSONB` 고속 검색, 벡터 검색(`pgvector`), 위경도 공간 연산(`PostGIS`)에서 압도적 성능을 제공하며 모든 상용 웹서비스와 SaaS의 1순위 표준입니다.

#### 2순위. SQLite (WAL 모드 — 포터블 및 소규모 서버 1순위)
- **동작 방식 및 드라이버**: 단일 로컬 파일(`app.db`) 기반이며, 파이썬 내장 `sqlite3` 또는 비동기 `aiosqlite`를 사용합니다.
- **장점 및 추천 대상**: 별도 DB 서버 설치가 전혀 필요 없고 파일 복사만으로 백업이 완료됩니다. `WAL` 모드 적용 시 동시 읽기/쓰기 성능이 대폭 향상되어 데스크톱 `.exe` 내장 DB, 사내 어드민 웹, 로컬 설정/로그 저장소에 최적입니다.

#### 3순위. Redis 7+ (인메모리 캐시 및 실시간 큐 표준)
- **동작 방식 및 드라이버**: 인메모리(RAM) Key-Value 스토어이며, `redis.asyncio` (`redis-py`)를 사용합니다.
- **장점 및 추천 대상**: 0.001초 이내 응답 속도를 제공하여 PostgreSQL의 보조 캐시 및 비동기 작업 큐로 짝지어 사용합니다. 실시간 접속 상태(Online/Offline, TTL 만료 활용), 세션 관리, API 속도 제한(Rate Limit)에 필수입니다.

#### 4순위. DuckDB (무서버 대용량 파일 OLAP 분석 1순위)
- **동작 방식 및 드라이버**: 인프로세스 분석용 컬럼형 DB(OLAP)이며, `duckdb` 패키지를 사용합니다.
- **장점 및 추천 대상**: 별도 서버 없이 대용량 `.xlsx`, `.csv`, `.parquet` 파일 수십 개를 직접 읽어 SQL `GROUP BY` 통계를 초고속 계산합니다. 수백만 건의 로그 및 통계 데이터 추출에 최적입니다.

#### 5순위. MariaDB / MySQL (기존 레거시 시스템 호환용)
- **동작 방식 및 드라이버**: 클라이언트-서버 RDBMS이며, 비동기 `aiomysql` 또는 `PyMySQL`을 사용합니다.
- **장점 및 추천 대상**: 신규 프로젝트에서는 PostgreSQL에 밀려 채택 빈도가 낮아졌으나, 기존에 구축된 구형 레거시 DB와 테이블/쿼리 호환성을 맞춰야 하는 유지보수 프로젝트에 한해 선택합니다.

### 2.2. [실전 코드] SQLite `Database is locked` 원천 차단 설정 (`SQLAlchemy 2.0 Async + WAL`)
로컬 프로그램이나 사내 웹에서 SQLite 연결 직후 아래 `PRAGMA` 5줄이 자동 실행되도록 설정하면 디스크 쓰기 속도가 5배 향상되고 읽기/쓰기 동시 충돌이 방지됩니다.

```python
# app/database.py
from sqlalchemy import event
from sqlalchemy.ext.asyncio import create_async_engine, async_sessionmaker, AsyncSession

DATABASE_URL = "sqlite+aiosqlite:///./data/app_local.db"

engine = create_async_engine(DATABASE_URL, echo=False)

@event.listens_for(engine.sync_engine, "connect")
def set_sqlite_pragma(dbapi_connection, connection_record):
    cursor = dbapi_connection.cursor()
    cursor.execute("PRAGMA journal_mode = WAL;")       # 읽기와 쓰기가 서로 블로킹하지 않음
    cursor.execute("PRAGMA synchronous = NORMAL;")     # 안전성 유지하며 디스크 쓰기 속도 향상
    cursor.execute("PRAGMA busy_timeout = 5000;")      # 동시 쓰기 충돌 시 최대 5초 대기
    cursor.execute("PRAGMA cache_size = -64000;")      # 64MB 메모리 캐시 할당
    cursor.execute("PRAGMA foreign_keys = ON;")        # 외래키 무결성 강제
    cursor.close()

AsyncSessionLocal = async_sessionmaker(engine, class_=AsyncSession, expire_on_commit=False)

async def get_db():
    async with AsyncSessionLocal() as session:
        yield session
```

## 5. 비동기 TCP 패킷 수신 및 한글 경로 이미지 처리 패턴

### 5.1. 비동기 TCP 소켓에서 패킷 분할 수신을 보장하는 `readexactly` 2단계 패턴
네트워크 환경에 따라 단일 패킷이 여러 조각(Fragment)으로 나뉘어 도착할 수 있으므로 단순 `read(1024)` 사용은 금지됩니다. 반드시 `asyncio.StreamReader.readexactly(n)`를 사용하여 고정 길이 헤더를 먼저 읽고, 헤더 내부의 `body_len` 필드 값만큼 바디를 읽어야 합니다.

```python
import asyncio
import struct

# 고정 헤더 (12 Byte, Big-Endian) 예시:
# > | 2s (매직바이트: 0xAA 0x55) | 6s (단말기ID) | I (바디길이 4Byte)
HEADER_FORMAT = ">2s6sI"
HEADER_SIZE = struct.calcsize(HEADER_FORMAT)  # 12 Byte

async def handle_tcp_client(reader: asyncio.StreamReader, writer: asyncio.StreamWriter):
    try:
        while True:
            # 1단계: 정확히 12바이트 헤더 수신 대기
            header_bytes = await asyncio.wait_for(reader.readexactly(HEADER_SIZE), timeout=60.0)
            magic, client_id_raw, body_len = struct.unpack(HEADER_FORMAT, header_bytes)

            if magic != b"\xAA\x55":
                raise ValueError(f"비정상 매직바이트 수신: {magic.hex()}")

            client_id = client_id_raw.rstrip(b"\x00").decode("utf-8", errors="replace")

            # 2단계: 헤더에 명시된 body_len 바이트만큼 정확히 데이터부 수신
            body_bytes = await asyncio.wait_for(reader.readexactly(body_len), timeout=120.0)

            print(f"[{client_id}] BODY={len(body_bytes)}B 수신 완료")
    except (asyncio.IncompleteReadError, asyncio.TimeoutError, ConnectionResetError):
        pass
    finally:
        writer.close()
        await writer.wait_closed()
```

### 5.2. 윈도우 한글 경로 이미지 로드 및 저장 (`np.fromfile` + `cv2.imdecode`)
윈도우 환경에서 `cv2.imread()`와 `cv2.imwrite()`는 경로에 한글이 포함되면 `None`을 반환하거나 저장에 실패합니다. 반드시 아래 NumPy 버퍼 조합을 사용합니다.

```python
import cv2
import numpy as np

def imread_korean(file_path: str) -> np.ndarray:
    """윈도우 한글 폴더 및 파일명에서도 안전하게 동작하는 OpenCV 이미지 로드 함수"""
    byte_array = np.fromfile(file_path, np.uint8)
    return cv2.imdecode(byte_array, cv2.IMREAD_COLOR)

def imwrite_korean(file_path: str, img: np.ndarray, jpg_quality: int = 92) -> bool:
    """윈도우 한글 경로로 고화질 JPEG 이미지를 저장하는 함수"""
    success, encoded = cv2.imencode(".jpg", img, [int(cv2.IMWRITE_JPEG_QUALITY), jpg_quality])
    if success:
        encoded.tofile(file_path)
    return success
```
