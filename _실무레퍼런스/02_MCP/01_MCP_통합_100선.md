# 실무 MCP 서버 통합 100선 레퍼런스 가이드

- **산정 기준**: 역대 누적 사용량, 실무 운영 안정성, AI 에이전트 연동 시 개발 생산성 기여도 종합 평가
- **작성 일자**: 2026년 10월 25일
- **문서 목적**: Antigravity 환경에서 즉각 도입 가능한 핵심 MCP(Model Context Protocol) 서버 100종의 아키텍처 배치 원칙과 실무 조합 가이드 제공

## 1. MCP 아키텍처 운영 원칙 및 스킬(Skills)과의 차이점

### 1.1 스킬(Skills)과 MCP(Model Context Protocol)의 본질적 차이
- **스킬(Skills - 두뇌와 지침)**: 마크다운 문서(`SKILL.md`)와 참조 스크립트로 구성된 정적 지식 체계입니다. 에이전트에게 프레임워크 컨벤션, 아키텍처 규칙, 코드 작성 표준을 가르치며 별도의 백그라운드 프로세스를 실행하지 않습니다.
- **MCP(Model Context Protocol - 손과 발)**: `npx`, `uvx`, `docker` 등을 통해 로컬이나 원격에서 실제로 구동되는 실행 프로세스입니다. 에이전트가 외부 데이터베이스에 쿼리를 날리고, 실제 브라우저를 조작하며, 외부 결제 API나 클라우드 인프라의 실시간 상태를 조회 및 변경할 수 있도록 도구(Tools)를 제공합니다.

### 1.2 Antigravity의 지연 로딩(Lazy Loading) 메커니즘
- **초기 컨텍스트 오염 방지**: 다수의 MCP 서버를 등록하더라도 Antigravity는 대화 시작 시 모든 도구의 JSON 스키마를 프롬프트에 한꺼번에 적재하지 않습니다.
- **온디맨드 스키마 조회**: 에이전트는 필요한 순간에만 서버 디렉터리의 도구 스키마를 읽어들인 뒤 `call_mcp_tool`을 호출하므로, 토큰 낭비와 응답 속도 저하 없이 수십 개의 MCP 도구를 효율적으로 운용할 수 있습니다.

### 1.3 공용(글로벌) 설정과 프로젝트 전용(로컬) 설정의 분리 원칙
- **공용 글로벌 설정 (`%USERPROFILE%\.gemini\config\mcp_config.json`)**: 프로젝트 종류와 무관하게 언제나 켜져 있어야 하며 외부 데몬 상태에 의존하지 않는 무상태(Stateless) 핵심 도구만 등록합니다. 대표적으로 `Context7`, `Playwright`, `Sequential Thinking`이 여기에 해당합니다.
- **프로젝트 전용 로컬 설정 (`<프로젝트루트>\.agents\mcp_config.json`)**: 특정 프로젝트의 기술 스택이나 비즈니스 도메인에 종속된 도구를 등록합니다.
- **중요 주의사항 (DB 및 Docker의 로컬 격리 필수)**: PostgreSQL, MySQL, Redis 등의 데이터베이스 MCP와 Docker MCP는 대상 엔진이나 컨테이너가 꺼져 있을 때 프로세스 연결 에러(Connection Refused)를 발생시킵니다. 이를 공용 글로벌 설정에 넣어두면 단순 프론트엔드나 문서 작업 시에도 에이전트 초기화 지연과 불필요한 에러 로그가 발생하므로, 반드시 해당 인프라를 실제로 구동하는 프로젝트의 로컬 설정 파일에만 등록해야 합니다.

### 1.4 설치 불필요 MCP (Antigravity 내장 도구 및 파이썬 스킬로 대체)
- **Filesystem MCP**: Antigravity의 내장 파일 도구(`read_file`, `write_file`, `edit_file`)가 훨씬 빠르고 정확하므로 별도 설치가 불필요합니다.
- **Git MCP**: 내장 터미널 실행 도구(`run_command`)를 통한 표준 Git CLI 제어가 충돌 해결 및 브랜치 관리에 더 안정적입니다.
- **Excel / PDF 생성 MCP**: 무거운 외부 서버를 띄우는 대신 워크스페이스 내 파이썬 스킬(`openpyxl`, `pdf-lib`, `reportlab`)을 호출하여 로컬 스크립트로 처리하는 것이 대용량 파일 제어에 유리합니다.
- **Time / Fetch 단순 조회 MCP**: 기본 시스템 명령어나 경량 내장 도구로 즉시 대체 가능합니다.

## 2. 실무 투입용 `mcp_config.json` 표준 템플릿 3종

### 2.1 공용 글로벌 필수 3대장 템플릿 (`%USERPROFILE%\.gemini\config\mcp_config.json`)
```json
{
  "mcpServers": {
    "context7": {
      "command": "npx",
      "args": ["-y", "@upstash/context7-mcp"]
    },
    "playwright": {
      "command": "npx",
      "args": ["-y", "@playwright/mcp@latest"]
    },
    "sequential-thinking": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-sequential-thinking"]
    }
  }
}
```

### 2.2 백엔드, 데이터베이스, 도커 프로젝트 전용 템플릿 (`<프로젝트>\.agents\mcp_config.json`)
```json
{
  "mcpServers": {
    "postgres": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-postgres",
        "postgresql://postgres:password@localhost:5432/mydb"
      ]
    },
    "redis": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-redis",
        "redis://localhost:6379"
      ]
    },
    "docker": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-docker"]
    }
  }
}
```

### 2.3 글로벌 및 국내 결제 연동 프로젝트 전용 템플릿 (`<프로젝트>\.agents\mcp_config.json`)
```json
{
  "mcpServers": {
    "tosspayments": {
      "command": "npx",
      "args": ["-y", "@tosspayments/integration-guide-mcp"]
    },
    "stripe": {
      "command": "npx",
      "args": ["-y", "@stripe/mcp", "--tools=all"],
      "env": {
        "STRIPE_SECRET_KEY": "sk_test_your_secret_key"
      }
    },
    "lemonsqueezy": {
      "command": "npx",
      "args": ["-y", "@lemonsqueezy/mcp-server"],
      "env": {
        "LEMONSQUEEZY_API_KEY": "your_api_key"
      }
    }
  }
}
```

## 3. 통합 MCP 1위 ~ 100위 상세 목록 (`001` ~ `100`)

### 부문 1: 코어 필수 MCP (001 ~ 010)

### 001. Context7 (`@upstash/context7-mcp`) [권장위치: 공용 글로벌]
- **역할**: 최신 라이브러리, 프레임워크, SDK의 공식 문서와 버전별 코드 예제를 실시간으로 검색하여 에이전트의 구버전 코드 환각(Hallucination)을 원천 차단합니다.
- **조합**: `[기술스택] 전 언어 및 최신 프레임워크 (Next.js 15, Tailwind v4, WXT 등)` + `[짝꿍 스킬] vercel-react-best-practices, chrome-mv3` + `[함께 쓰는 MCP] Sequential Thinking`
- **명령**: `npx -y @upstash/context7-mcp`

### 002. Playwright (`@playwright/mcp@latest`) [권장위치: 공용 글로벌]
- **역할**: 실제 헤드리스 또는 일반 브라우저를 구동하여 웹 페이지 렌더링 검증, DOM 스냅샷 추출, 클릭 및 폼 입력 자동화, E2E 테스트 디버깅을 수행합니다.
- **조합**: `[기술스택] React, Vue, Next.js, Chrome Extension` + `[짝꿍 스킬] playwright-best-practices, webapp-testing` + `[함께 쓰는 MCP] Context7`
- **명령**: `npx -y @playwright/mcp@latest`

### 003. Sequential Thinking (`@modelcontextprotocol/server-sequential-thinking`) [권장위치: 공용 글로벌]
- **역할**: 복잡한 아키텍처 설계나 다단계 버그 추적 시 사고 과정을 단계별 트리로 분해하고 가설 검증 및 역추적(Backtracking)을 수행하도록 돕습니다.
- **조합**: `[기술스택] 대규모 리팩터링, 분산 시스템 설계, 난해한 비동기 버그 분석` + `[짝꿍 스킬] brainstorming, systematic-debugging` + `[함께 쓰는 MCP] Context7, Memory`

### 004. PostgreSQL (`@modelcontextprotocol/server-postgres`) [권장위치: 프로젝트 전용]
- **역할**: 로컬 또는 개발용 PostgreSQL 데이터베이스에 직접 연결하여 테이블 스키마 조회, 인덱스 상태 점검, 안전한 읽기 쿼리 실행 및 실행 계획(EXPLAIN) 분석을 수행합니다.
- **조합**: `[기술스택] PostgreSQL, Prisma, Drizzle ORM, FastAPI, NestJS` + `[짝꿍 스킬] supabase-postgres-best-practices` + `[함께 쓰는 MCP] Prisma, Redis`

### 005. SQLite (`mcp-server-sqlite`) [권장위치: 프로젝트 전용]
- **역할**: 별도의 DB 데몬 없이 로컬 단일 파일(`.db`, `.sqlite`) 기반의 데이터베이스를 즉시 생성하고 테이블 조회, 데이터 적재 및 통계 분석 쿼리를 실행합니다.

### 006. Docker (`@modelcontextprotocol/server-docker`) [권장위치: 프로젝트 전용]

- **조합**: `[기술스택] Docker, Docker Compose, 마이크로서비스 백엔드` + `[짝꿍 스킬] docker-expert, backend-patterns` + `[함께 쓰는 MCP] PostgreSQL, Redis, Portainer`

- **조합**: `[기술스택] Redis, BullMQ, Celery, 고성능 API 서버` + `[짝꿍 스킬] backend-patterns` + `[함께 쓰는 MCP] PostgreSQL, Docker`
